# Альфа-Авто 6.1 — учебный тренажёр (прототип сквозного процесса)

**Статус:** функциональная автономная учебная сборка для проверки сценариев и согласования с владельцем процесса. **Не является копией или заменой рабочей 1С.** Прямой доступ к действующей учебной/боевой конфигурации 1С и исходникам сайта ea-itus.ru в этой сессии получить не удалось, поэтому визуальное и функциональное соответствие реальным формам не заявляется.

## Что работает

- UI в стиле 1С: рабочий стол, «Событие», «Заявка на ремонт», «Заказ-наряд», «Калькуляция», «Задачи CRM», MAX, результаты;
- переключение между 4 учебными ролями: мастер-приёмщик, ОЗЧ, исполнитель, координатор;
- отработка последовательности **Событие → заявка на ремонт → ЗН → дефектовка → авто-КП → проценка ОЗЧ → согласование → закрытие ЗН**;
- запись/проведение события с проверкой «Контактное лицо», «Причина обращения», «Договорённость с клиентом» и связанного документа;
- ручная «Задача CRM» из события: вид «Телефонный звонок»/«Напоминание», тема, содержание, ответственный, поля дат КО (в пределах 60 дней) и флаг «Общий вопрос», обязательный результат исполнения;
- отмена события и автоматическая задача координатору «Контроль отмены события»; возврат с комментарием формирует «Дожим клиента»;
- при завершении дефектовки исполнитель создаёт автоматическую КП и задачу мастеру, защита от повторной генерации;
- при нажатии «Проценить» задача мастера завершается, возникает задача ОЗЧ; после проценки и статуса «Согласование» возникает задача мастеру;
- согласование каждой позиции КП, перенос согласованных авторабот и товаров в учебный ЗН;
- финансовая блокировка и путь «Запрос → согласование координатором → разблокировка»;
- учебный MAX с проверкой согласия на обработку персональных данных (никаких реальных сообщений);
- 3 режима: обучение, практика, экзамен; контроль итоговых условий, журнал действий, выгрузка результатов в JSON;
- сохранение локального прогресса в браузере (localStorage), сброс и новый сценарий.

## Запуск

Никакие зависимости для просмотра не нужны: откройте `index.html` браузером. Если браузер ограничивает доступ к локальным файлам, выполните в папке проекта:

```bash
python -m http.server 8787
```

Откройте `http://127.0.0.1:8787/`.

Для проверки движка потребуется Node.js 20+:

```bash
node --test tests/test-engine.js
```

При наличии Python Playwright и Chromium можно проверить всё приложение браузерным тестом `python tests/browser-smoke.py`. Этот тест использует встраивание всех статических файлов в страницу и не обращается к внешнему серверу.

## Как пройти главный сценарий

1. Роль **Мастер-приёмщик**: откройте «Событие», заполните данные клиента и автомобиля из задания справа. Выберите «Диагностика», в договорённости запишите жалобу и план. Нажмите «Записать».
2. Откройте «Заявка на ремонт», выберите дату/время, нажмите «Записать заявку».
3. Вернитесь к событию, нажмите «Провести и закрыть». Далее откройте «Заказ-наряд» и создайте ЗН.
4. Переключитесь на **Исполнителя**, откройте «Задачи CRM», примите задачу. Откройте «Заказ-наряд», нажмите «Завершить дефектовку».
5. Вернитесь к **Мастеру-приёмщику**, примите новую задачу «Подготовить КП». Откройте «Калькуляция», добавьте автоработу и товар. Нажмите «Проценить».
6. Переключитесь на **ОЗЧ**, примите задачу, откройте КП, заполните цену и поставщика, нажмите «Применить». Переведите КП в статус «Согласование».
7. Переключитесь на **Мастера-приёмщика**, примите задачу согласования, укажите результат по каждой позиции и комментарий. Завершите согласование.
8. Откройте ЗН, закройте его и проверьте вкладку «Результаты». При корректном прохождении будет 100%.

## Соответствие источникам

Реализованные проверки и переходы опираются на документы проекта:

- «CRM Событие и система задач (1).pdf» — события, передача задач, роль координатора, «Дожим клиента», условия проведения;
- «Изменения в задаче CRM.docx» — предлагаемые/желаемые даты и «Общий вопрос»;
- «Автоматическая КП по дефектовке.docx» — запуск по дефектовке, задача мастеру, «Проценить» → ОЗЧ → «Согласование»;
- «Работа КП(1).docx» — работы, товары, отметки «Согласован», «Рекомендация», «Деталь клиента»;
- «Работа с мессенджером «MAX».docx» — приглашение и блокировка переписки без согласия;
- «Инструкция по работе с заблокированными контрагентами ФРОНТЛАЙН.docx» — блокировка и согласование;
- «Инструкция_мастера-приемщика_1С_Альфа-Авто_6.1(2).docx» — обзор рабочего процесса.

Все цены, коды, контакты, автомобиль и номенклатура демонстрационные. Отдельные экранные элементы, которые невозможно достоверно воспроизвести без доступа к актуальной конфигурации, упрощены.

## Что не реализовано и требует подключения к настоящему проекту

- точная сверка форм, кнопок, подсистем, скрытых реквизитов и прав с 1С по всем ролям;
- миграция существующих восьми модулей тренажёра без потери достигнутого — **исходный код действующего тренажёра отсутствует в доступных источниках**;
- калькуляция по реальным номенклатуре и нормативам 1С, документам подразделений и вариантам комплектации;
- полный цикл склада (РСО/ПСО, перемещения, резервы), оплаты, реализации и выдачи; инструкции этих ролей требуют уточнений;
- многопользовательская серверная база, аутентификация персонала и отчётность руководителей по реальным людям;
- интеграция с телефонией, 1С, MAX, Email и смежными сервисами (во избежание отправки реальных данных);
- автоматическое развертывание на Timeweb и сравнение с текущим `https://ea-itus.ru/p/alfa-auto-trainer/`.

**До верификации использовать только для демонстрации и внутреннего тестирования, не как аттестационную платформу.**

## Развертывание на тестовом сайте

Копируйте содержимое каталога в **отдельный тестовый путь**, например `/p/alfa-auto-trainer-preview/`, если такой маршрут подготовлен системным администратором. Не заменяйте файлы текущего `/p/alfa-auto-trainer/`. Приложение полностью статическое: `index.html`, `styles.css`, `engine.js`, `app.js`; серверной БД нет. Перед публикацией в локальной сети учтите, что любой пользователь может переключать роли и просматривать учебные данные; это демонстрационный режим без входа по персональным учётным записям.
