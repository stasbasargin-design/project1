# I-MAX: обязательный протокол работы и выпуска

Эти правила обязательны для любого агента и любого компьютера в репозитории.

## Перед изменениями

1. Выполни `git fetch --prune origin`.
2. Проверь `origin/main`, связанные открытые PR/ветки и доступные GitHub Actions; старые локальные копии, архивы и неподтверждённые версии не считай актуальными.
3. Покажи пользователю текущую ветку, `git status --short`, SHA `origin/main` и SHA текущего `HEAD`.
4. Для новой задачи создай отдельную ветку от актуального `origin/main`: `feature/<задача>` или `fix/<задача>`. Не работай вдвоём в одной ветке.
5. Если production SHA или его версия не подтверждены из GitHub/Timeweb, не назначай и не меняй версию на основании предположения: остановись и запроси подтверждённую базу. Это не запрещает чтение кода, подготовку тестов и локальную диагностику от подтверждённого `origin/main`.

## Версии

- Каждое изменение пользовательского поведения выпускается отдельной новой версией. Версия не переиспользуется и не понижается.
- Перед выпуском должны быть синхронизированы runtime-версия I-MAX, `app-max/package.json`, Android `versionName`, Android `versionCode` и release-заявка.
- Существующее расхождение версий сначала устраняется отдельной согласованной задачей от подтверждённого production SHA; функциональные изменения не смешиваются с этой задачей.

## Проверки и передача

1. Перед commit/PR повтори `git fetch --prune origin`. Если `origin/main` изменился, обнови свою ветку только после проверки diff и повтори проверки.
2. Используй lock-файл: `npm ci`, затем `npm test` и `npm run build`.
3. В отчёте всегда укажи base SHA, итоговый SHA, версию, список файлов, результаты проверок и то, что не проверено.
4. Для передачи второму Cursor сформируй заполненную инструкцию по `docs/CURSOR_RELEASE_COMMAND_TEMPLATE.md`.

## Выпуск

- Не делай push в `main`, production-deploy или запуск `deploy-max.yml` без явного подтверждения владельца для точных версии и SHA.
- После подтверждения release-commit попадает в `main` только штатным PR-процессом. Это запускает существующие GitHub Actions для Timeweb и Android APK.
- Не подменяй GitHub/Timeweb-версию ручной загрузкой файлов и не включай в выпуск посторонние коммиты.
