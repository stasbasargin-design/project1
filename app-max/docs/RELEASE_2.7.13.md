# I-MAX 2.7.13 — стабилизация перед общим запуском

База: актуальный GitHub main `894548105b0e8291e1952a6a2f876bde8de41f28`, production 2.7.11.
Ветка: `fix/prelaunch-stabilization`. Runtime/npm/Android: 2.7.13; versionCode 2713.
Владелец разрешил исправления, APK и production deployment в текущей задаче 29.10.2026.
Версия 2.7.12 не переиспользуется; её отдельная ветка снятия видео-лимита не включена.

## Изменения

- Изоляция очереди по владельцу, API и поколению сессии; выход останавливает работу
  старой сессии и не даёт поздним ответам изменить новую.
- Неизменяемые orderRef/documentRef/тело завершения, зависимость complete от подтверждения
  вложений, продолжение после ручного повтора, восстановление по lease/online/foreground.
- Постоянный доступ к очереди и отчётам после перезапуска. Сохранённые пакеты и IDB
  schema 2 не удаляются. После запроса complete редактирование исходного документа
  блокируется; другой ЗН остаётся доступен.
- Постоянная очередь текста/файлов обоих чатов, честные состояния ошибки; защита
  чтения медиа от смены переписки и пользователя во время загрузки.
- Асинхронные кнопки удерживают индикатор и блокировку; повторный клик не создаёт
  вторую операцию. Logout очищает локальную сессию даже при ошибке native unregister.
- Точные серверные роли администратора сохранены; пустые права обычного сотрудника
  больше не открывают разделы.
- Единая оболочка, закреплённые доступные разделы в чатах/landscape, safe-area и
  высота клавиатуры. Android Back использует lifecycle-aware AndroidX callback.
- Повтор серверной регистрации FCM, отмена позднего QR-результата, jsQR при сбое
  BarcodeDetector. Firebase package и каналы Push не меняются.
- build-info.json и health сообщают точную версию/SHA. Deployment проверяет именно
  SHA workflow, а не произвольный последний main.
- Переполнение тела запроса возвращает HTTP 413; логи содержат только размеры
  запросов/ответов, без содержимого файлов. Совместимые обновления зависимостей.

## Автоматическая проверка

`npm ci`, полный `npm test` (26 наборов), `npm run test:review`, `npm run build`.
Браузерные тесты обязательны в CI, отсутствие браузера не считается успехом.
Проверены размеры 360/393/800/1200 px, landscape 852×393, моделирование safe-area
и visualViewport при клавиатуре. Реальный Android release compile выполнен.

Дополнительные регрессии: смена владельца во время отправки; смена ЗН во время
complete; 422/ручной повтор/возобновление complete; сохранённые отчёты после входа;
истечение lease; двойной клик; поздний QR/media callback; FCM subscribe retry;
чат-пакет до первого HTTP и восстановление с прежними идентификаторами.

## Подпись и APK

GitHub Actions создаёт явно обозначенный unsigned release, не debug APK со случайной
подписью. До локального подписания такой артефакт нельзя выдавать пользователям.
Подписание выполняется существующим ключом на компьютере владельца. Ключ не
загружается в GitHub и не включается в репозиторий.

Ожидаемый SHA-256 сертификата:
`906BA322884FCA8C92C2D884CDEBB8EC8F4EB3D527BAF7D06929970BA77BCB47`.

Это совместимо с прежней группой APK с этим сертификатом. Для установок с другими
историческими CI/release-сертификатами совместимость не заявляется. Не удалять
рабочее приложение ради обновления, пока в нём могут находиться неотправленные данные.

Итоговый подписанный файл: `I-MAX-2.7.13.apk`. В GitHub Release публикуются этот файл,
SHA256SUMS и документ 1С; в APK проверяются package, versionCode, production API,
build-info.commit и сертификат.

## Deployment и откат

Перед merge администратор сохраняет прежний `/usr/local/bin/deploy-max.sh`, проверяет
`bash -n` нового `app-max/scripts/deploy-max.sh` и устанавливает именно этот скрипт.
Это обновляет механизм выпуска, но не перезапускает приложение.

Штатный merge PR запускает workflow: обязательные тесты → exact-SHA deployment.
Скрипт создаёт отдельный build-worktree и свежий staging, не копирует секреты,
сохраняет полный application backup и предыдущий рабочий каталог. После атомарного
переключения проверяет public health с SHA, manifest, Service Worker и Web Push.
При ошибке или HUP/TERM во время переключения выполняется проверяемый откат.

Имена фактических backup/previous каталогов и SHA фиксируются в журнале успешного
Actions run и финальном отчёте. При ручном откате сначала подтвердить точные пути,
остановить только itus-max, сохранить неудачную версию отдельным каталогом, вернуть
предыдущий каталог через `mv -T`, запустить сервис и проверить health. Очередь на
устройствах и env-файлы не очищать.

## Требуется отдельная живая приёмка

Физические Xiaomi Android 16, другой Android, iPhone PWA и Яндекс Windows; реальная
1С при потерянном ответе/422/смене ЗН; отсутствие дублей и порядок entries→complete.
Сборка и локальные заглушки не считаются проверкой транзакций 1С или реальной камеры.

Для 1С: `1C_STABILIZATION_2.7.13.md`. Важны действующая идемпотентность всех чат-методов,
безопасная обработка 422, серверная проверка личности/прав и измерение таймаутов.
Видеолимит 15 МиБ сохранён до согласования надёжного транспорта крупных роликов.
Закрытый браузер не гарантирует постоянное выполнение JavaScript; очередь сохраняется
и возобновляется после открытия и входа владельца.

## Передача другому разработчику

Сначала fetch GitHub, сверить merge SHA с `/health` и `build-info.json`. Не брать
старый локальный checkout. Для следующего изменения создать новую ветку от main.
Не заменять APK случайно подписанным debug-артефактом. Не переносить ключ подписи
и серверные env в репозиторий или переписку.
