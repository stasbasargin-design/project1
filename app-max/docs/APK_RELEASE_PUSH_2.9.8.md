# I-MAX 2.9.8: уведомления о выпуске Android APK

Сохранён весь проверенный кандидат f646dce732b20e94b2959308e4682c6b9c8576b7.
Версия 2.9.8 / 2908 сохранена по прямому указанию владельца для первого боевого
выпуска. Production base: 5269f8c5d6a993729c0eff230d1a582e809206e0 (2.9.3).

## Устройство и версия

Timeweb наблюдает существующий /notifications/push/subscribe после HTTP 200 и
data.registered:true. Запрос и ответ 1С не изменяются. Только Android и распознанная
версия из существующего version сохраняются приватно рядом с Push installation.
Привязка проверяется по сотруднику, instance и контуру; eligible только enabled
установки с подтверждённым bind/activation. Web и неизвестные версии исключены.
Отдельных методов или изменения логики 1С для уведомлений о выпуске не требуется.

Первое внедрение: существующие APK должны хотя бы раз запуститься/авторизоваться
после обновления сервера, чтобы повторить штатную регистрацию Push. Старые хеши
токенов восстановить в токены невозможно; устройства без новой регистрации не
выдаются за охваченные рассылкой. Токены не выводятся в HTTP-ответах/журналах.

## Публикация

После проверки APK оператор атомарно публикует latest.json с notify:true.
Старые manifest без этого флага ничего не рассылают. Только этот валидный manifest,
совпадение размера/формата и фактического SHA256 APK разрешают отправку. Backend
проверяет раз в минуту и после bind; простой серверный deploy не является триггером.
Production и test имеют разные каталоги updates; рассылка ограничена WEB_PUSH_CONTEXT.

Версия установленного локального UI сравнивается по major/minor/patch с версией
опубликованного APK. Только строго старые версии; равные, более новые, неизвестные,
web, paused и чужой контур исключены. Android дополнительно проверяет фактический
PackageManager versionCode при доставке и отбрасывает уже установленные обновления.

## Без повторов и смешивания

До FCM сохраняется durable claim (установка, контур, versionCode), общая между
процессами. Перезапуск, повторная публикация, новый activation и ротация токена не
повторяют попытку для этой установки и версии. Потеря ответа FCM остаётся uncertain;
автоматически не повторяется. Это at-most-once попытка, а не гарантия доставки.
Проверка обновлений при входе остаётся запасным способом.

FCM содержит environment/activationId. Перед отправкой они перепроверяются,
Android отбрасывает запоздалую доставку после смены контура. Сохраняется максимальный
номер показанного обновления по контуру; один eventId также задаёт ID уведомления.

Новый type app_update_available открывает только существующий fixed-origin
обновлятор, без URL из Push, /orders/get, отправок файлов или завершения документов.
Установка всё равно требует системного подтверждения и текущих проверок очередей/
редакторов. Уже установленные старые APK нельзя изменить этим сообщением: первое
уведомление открывает приложение; доступны проверка при входе и Настройки → Проверить
обновление. Начиная с 2.9.8 есть прямой обработчик нового типа.

## Проверки и выпуск

Тесты: старые/равные/новые/неизвестные версии, web, paused; concurrency/restart,
ротация токена, потеря FCM ответа, повреждённый APK, выключенная рассылка,
смена контура, JVM native-фильтр; браузерная навигация/дедупликация Push без
чужих HTTP-запросов и сохранение существующих guards очереди/черновика.

Владелец разрешил в текущем запросе после успешных проверок теста сразу выполнить
штатный production-выпуск и публикацию APK на Timeweb. Это условное разрешение
распространяется только на проверенный финальный SHA этой задачи; перед merge
проверяются main/base, exact CI и diff. Ссылка APK в чат не требуется.
Финальный release SHA определяется штатным merge PR; web/APK собираются Actions
именно из него. Сохраняются backup/rollback и прежний signer.

Отдельная защита старых версий реакций 1С остаётся описанной в REACTION_CODES_1C_2.9.8.md;
она не подменяется уведомлениями и не затрагивает действующие клиентские чаты.
