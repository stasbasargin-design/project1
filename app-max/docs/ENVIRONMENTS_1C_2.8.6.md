# Подключения 1С в I-MAX 2.8.6

Переключение доступно в профиле через «Подключение к 1С». После подтверждения приложение заново входит в выбранную базу. По умолчанию используется боевая 1С. Явно выбранная пользователем база запоминается. При первом обновлении сохранённый MAX ID используется для нового входа в боевую базу, без переноса данных сессии. Старые очереди сохраняют тестовый контур. Отметка в шапке показывает активную базу.

## Публикации

- Тестовая `https://1c.eazia.ru/aa6_ea_test9/ru/hs/max-service`.
- Боевая `https://1c.eazia.ru/aa6_ea/ru/hs/max-service`.

I-MAX выбирает только настроенные на сервере подключения. Произвольный URL от клиента не принимается. Тестовый API сохраняет прежний маршрут и пространство старых очередей. Боевой API использует `/contours/production/api/1c` внутри базового пути приложения. Авторизация, чаты, черновики, анкеты и медиа разделены. Пакет сохраняет свои requestId, clientEntryId/clientMessageId, содержимое и исходную базу. Полностью загруженный в S3 пакет может закончить импорт в своей базе после переключения. Файл, оставшийся на устройстве, возобновляется при возвращении пользователя в его контур.

## Что нужно настроить в 1С

Методы обработки ЗН, записей, файлов и завершения сохраняют прежние JSON-контракты. Обе публикации должны иметь действующие `/auth/max`, маршруты чатов и регистрации `/notifications/push/subscribe` и `/notifications/push/unsubscribe`.

Для тестовой базы адреса отправки Push сохраняются:

- Android `POST https://ea-itus.ru/p/max-service/api/push/dispatch`.
- Web `POST https://ea-itus.ru/p/max-service/api/push/web/dispatch`.

Для боевой базы разработчик 1С должен задать:

- Android `POST https://ea-itus.ru/p/max-service/contours/production/api/push/dispatch`.
- Web `POST https://ea-itus.ru/p/max-service/contours/production/api/push/web/dispatch`.

Авторизация маршрутов остаётся существующей серверной. Секреты берутся из защищённых настроек интеграции. Поле контура в тело бизнес-запросов добавлять не требуется. Нельзя направлять события обеих баз на один старый адрес. Сервер определяет источник по маршруту, а не по заявлению браузера. На тестовом домене для проверки боевого канала используется тот же суффикс `/contours/production/api/push/...`.

## Изоляция уведомлений

Новые установки подтверждают активную базу в отдельном серверном реестре после успешной регистрации в 1С. Старые регистрации остаются известными реестру и блокируются при переключении. Поздний ответ регистрации не может вернуть прежний контур. Неизвестные установки не получают Push из боевого маршрута. Android обрабатывает уведомления нового формата в нативном сервисе перед показом, Web — в Service Worker. В идентификатор доставки входит активация установки, чтобы отсечь событие, задержанное до переключения. Переключение при неподтверждённом отключении Push требует повторной попытки. Доступ пользователя к объектам по-прежнему проверяется соответствующей 1С.

## Сервер

Закрытый env-файл задаёт `ONE_C_PRODUCTION_TARGET`, `ONE_C_PRODUCTION_TOKEN`, при необходимости `ONE_C_PRODUCTION_BASIC_USER` и `ONE_C_PRODUCTION_BASIC_PASSWORD`, а также `PUSH_INSTALLATIONS_DIR`. Значения доступов и S3 не попадают в веб-конфигурацию или APK. Реестр Push общий для тестового и рабочего размещения I-MAX. Для второго подключения медиа использует отдельный подкаталог постоянного состояния и отдельный S3-префикс, вычисляемый по фактическому upstream.

Перед выпуском нужны проверки входа, чатов с одинаковыми ID, переключения во время отправки, возврата к старой очереди, поздних Push и геометрии входа на разных размерах экрана. При откате восстанавливаются application и deploy-скрипт из сохранённой копии. Очереди устройств, постоянные состояния медиа и реестр Push не удаляются.

APK, устанавливаемый напрямую из файла, требует разрешения Android для выбранного источника установки. Подпись обеспечивает совместимость обновления. Распространение через доверенный магазин или управляемый корпоративный канал настраивается отдельно.
