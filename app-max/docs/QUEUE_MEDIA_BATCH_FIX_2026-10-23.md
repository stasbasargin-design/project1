# Исправление пакетной отправки вложений — 23.10.2026

## Доказанная причина

Прежний media picker обрабатывал выбранные файлы последовательно и ожидал полный сетевой ответ 1С для каждого файла. Операция IndexedDB создавалась только внутри этого цикла. Закрытие формы очищало `session`, поэтому ещё не обработанные файлы не имели ни сохранённого содержимого, ни операции очереди и после повторного входа не могли восстановиться.

## Исправленный жизненный цикл

1. При нажатии «Отправить» фиксируется неизменяемый снимок полного списка файлов и их `clientEntryId`.
2. Все файлы подготавливаются с прежним профилем сжатия.
3. Полный пакет операций одним transaction сохраняется в IndexedDB: содержимое файла в теле запроса, `orderRef`, фактический `documentRef`, маршрут и идентификаторы.
4. Ошибка любой подготовки или transaction оставляет окно открытым и не выдаётся за успех.
5. Во время локального сохранения ручное закрытие блокируется. После commit IndexedDB окно закрывается автоматически, не ожидая HTTP-ответов 1С.
6. Фоновый worker читает только сохранённые операции и не зависит от DOM, формы или выбранного сейчас заказ-наряда.
7. При входе того же пользователя в тот же контур операции `entry` восстанавливаются раньше `complete`.
8. `complete` для приёмки и дефектовки блокируется, пока в очереди остаётся хотя бы одна операция `entry` с тем же `documentRef`.

## Автоматические проверки

- пакет из трёх различимых файлов целиком передаётся в локальную фиксацию;
- ручное закрытие блокируется до фиксации полного пакета;
- окно закрывается сразу после локальной фиксации;
- три операции существуют до начала транспорта и сохраняют неизменяемые тела и разные стабильные `clientEntryId`;
- действуют прежние проверки потерянного ответа, лимита пяти попыток, HTTP 422, межвкладочной блокировки и повторов `complete` с прежним `requestId`.

Живая проверка 1С выполняется отдельно только на согласованных тестовых документах. Production, Android, Push, чаты, иконки и профиль сжатия этим исправлением не изменяются.
