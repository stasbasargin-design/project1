# Авторы сообщений и переходы из Push

## Автор сообщения

Для истории чатов единственным источником автора служат данные 1С. Текущий
контракт `1C_HTTP_METHODS_RELEASE.json` определяет `authorName` для ответов
`/clients/messages/list` и `/internal-chat/messages/list`.

Клиент также сохраняет уже поддерживаемые полями интеграции варианты
`senderName` и `from`, в указанном порядке приоритета после `authorName`.
Если ни одного поля нет, UI показывает «Отправитель не указан». Он **не**
подставляет имя текущей сессии, последнего отправителя, исполнителя ЗН или
значение из кеша другого сообщения.

После ответа на отправку без данных автора клиент запрашивает облегчённую
историю (`includeAttachmentContent:false`). Кеш не заменяет ранее известного
автора неполным ответом. Поэтому при повторном открытии, обновлении и смене
пользователя авторами остаются только значения из интеграции.

При расширении 1С-контракта новые поля автора нужно сначала добавить в
`normalizeMessage` и в регрессионные тесты. Не используйте поля профиля
текущего пользователя как резервный источник для уже подтверждённого сервером
сообщения.

## Push-навигация

`internal_chat_message` использует `topicRef`; в приложении он передаётся как
идентификатор существующей внутренней переписки в `messenger.openThread('staff',
topicRef)`. Вызов получает актуальную историю и соблюдает права вкладки «Чат».

`quality_control_requested` использует `orderRef`. Приложение получает этот
заказ-наряд через существующий `/orders/get`, открывает вкладку технолога и
загружает контроль качества через существующий `/quality/start`.

Если Push открыт до авторизации, цель сохраняется только в памяти приложения и
выполняется после успешной инициализации. При выходе она очищается. Повторная
обработка одного `eventId`/`notificationId` не создаёт повторный переход.
