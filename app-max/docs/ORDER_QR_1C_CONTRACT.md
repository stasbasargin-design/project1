# Минимальный контракт 1С: поиск ЗН по QR

Статус: требуется подтверждение разработчика 1С. Клиент использует существующий `POST /orders/search`; новый параметр не считается работающим до проверки HTTP-сервиса 1С.

## Требуемое поведение существующего метода

Запрос сохраняет стандартный auth-конверт I-MAX и передаёт:

```json
{
  "search": "00A7Z",
  "searchBy": ["orderNumber"]
}
```

- `search` — строка ровно из пяти символов; начальные нули и регистр передаются без числового преобразования.
- 1С ищет среди всех ЗН, доступных авторизованному сотруднику, а не среди списка, ранее загруженного клиентом.
- Поиск обязан учитывать совпадения вне первой страницы и вне обычного ограничения выдачи `/orders/list`. Если `/orders/search` внутренне постраничный, 1С должна либо выполнить полный поиск до формирования ответа, либо вернуть документированный cursor-контракт. Клиент не придумывает cursor-параметры без подтверждения 1С.
- Для `searchBy: ["orderNumber"]` необходимо подтвердить поиск по вхождению либо окончанию номера. Клиент дополнительно оставляет только записи, полный `orderNumber` которых оканчивается на `search`.
- Ответ использует обычный массив `orders`/`items` метода `/orders/search` и возвращает `orderRef`, полный `orderNumber`, а также только разрешённые для сотрудника `vehicle.model` и `vehicle.plate`.
- Ноль, один и несколько результатов являются штатными ответами. Метод не должен сам выбирать первый ЗН.
- Клиентская проверка `orderNumber.endsWith(search)` является только защитной проверкой ответа. Она не заменяет полный серверный поиск.

## Приёмочная проверка 1С

1. `search="00123"` не превращается в `123`.
2. `search="00A7Z"` поддерживает буквы.
3. Возвращаются два разных полных номера с одинаковым окончанием, если оба доступны сотруднику.
4. Нужный ЗН находится, даже если его нет на первой странице `/orders/list` и в первоначальном локальном списке клиента.
5. Недоступный сотруднику ЗН не возвращается.
6. Метод не меняет текущего пользователя и не вызывает сценарии `/auth/qr/*`.

До письменного подтверждения пунктов выше контракт имеет статус `ОЖИДАЕТ ПОДТВЕРЖДЕНИЯ 1С`; наличие клиентского кода не считается доказательством поддержки полной выдачи.
