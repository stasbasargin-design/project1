# I-MAX 2.9.8: состояние кнопки обновления истории

Узкое исправление кандидата 2.9.8 по запросу владельца перед боевым выпуском.
Полная тестовая база: b2d2dc41e35b7842f5cc7507f4dcc7b6f697dd22.
Production/main: 5269f8c5d6a993729c0eff230d1a582e809206e0 (2.9.3).
Номер ещё не выпущенного кандидата 2.9.8 сохранён по прямому указанию владельца.

Причина: loadMessages выставляет busy и рисует заголовок с disabled-кнопкой;
после завершения частичный paintHistory меняет только историю, поэтому состояние
кнопки остаётся прежним. Исправление синхронизирует disabled, aria-busy и
is-pending с текущим busy выбранного чата при частичной перерисовке.

HTTP-маршруты, тела, requestId, авторизация, чаты/контуры, очереди, транспорт файлов,
повторы, Push, фоновые задачи и Android-подпись не меняются. Composer не заменяется
при завершении частичного обновления; текст и положение курсора сохраняются.

Браузерная регрессия для сотрудников и клиентов:
- Кнопка доступна после первого открытия.
- Пока ответ удерживается, кнопка disabled с aria-busy:true.
- Повторный клик не создаёт второй запрос.
- После успеха и ошибки кнопка снова доступна, aria-busy:false, is-pending снят.
- Повтор после ошибки работает.
- Текст, узел composer и курсор, введённые во время ожидания, сохраняются.

До изменения регрессия воспроизвела ошибку: staff refresh is enabled after opening,
actual true / expected false. Полные проверки и публикация выполняются только на
max-test; production и основной канал APK не обновляются.

Для 1С остаётся отдельная серверная защита старых клиентов, описанная в
REACTION_CODES_1C_2.9.8.md: reactions:false для 2.9.7 и ниже/неизвестной версии,
если Unicode не поддерживается. Проверка версии нужна также в messages/react,
поскольку старый клиент мог сохранить ранее выданную capability.
