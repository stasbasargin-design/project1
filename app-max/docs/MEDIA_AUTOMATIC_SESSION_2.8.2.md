# I-MAX 2.8.2 — автоматическое подключение файлов

База: GitHub main `f618d87c1e9f6fcaf66bde614f212a1e30832d24`, 2.8.1.
Runtime/npm/Android: 2.8.2; versionCode 2802; пакет `ru.eazia.imax`.

## Для сотрудников

Вводить код подключения больше не требуется. После обычного входа приложение
автоматически получает доступ к файловому буферу. Подключение обновляется
автоматически при истечении срока или отзыве ключа. В настройках осталась
информация об отправке крупных файлов и необязательная кнопка проверки связи.
Смена пользователя изолирует его доступ и очередь от предыдущего сотрудника.

## Сервер

Новый `POST /api/media/session` получает конверт текущей авторизации.
Сервер самостоятельно вызывает существующий `/auth/max` в 1С, проверяет
успешный ответ и наличие сотрудника. Клиентский флаг «вход выполнен» не
используется как разрешение. Идентификаторы в конверте должны совпадать.
После проверки выдаётся случайный индивидуальный ключ на 30 дней; на сервере
хранится только его хэш. Ключ изолирован по пользователю и API-контуру.
Несколько одновременных действий используют одно подключение. Запоздалый
ответ после смены пользователя не записывает ключ в его сессию.

Проверки прав на конкретный ЗН/документ/чат выполняются при операциях с буфером.
S3-ключи остаются в закрытом env сервера. Секреты не включены в сайт или APK.
Ограничение частоты обновления применяется к сотруднику, а не ко всем людям
за общим Nginx. Число одновременных проверок 1С ограничено.

Используется существующая модель входа по MAX ID: `/auth/max` подтверждает
наличие сотрудника и его доступ в 1С, но не доказывает владение введённым ID.
Этот выпуск не добавляет подтверждение личности MAX/SSO. Удаление ручного
кода и сохранение текущей модели доступа явно согласованы владельцем.

## 1С и совместимость

Для удаления кода изменений в 1С не требуется. Используется существующий
`/auth/max`. Основной и тестовый сайты остаются на `aa6_ea_test9`.
Операции S3, полный файл в `contentBase64`, стабильные requestId/clientEntryId,
журнал квитанций и завершение после всех частей сохранены. Схема IndexedDB
остаётся v4; очищать очередь или сбрасывать IDs нельзя.

Существующие подключения 2.8.1 продолжают действовать. Старый серверный
маршрут кода сохранён для совместимости, но новый клиент его не использует.
Файлы >10 МиБ используют S3 после сжатия фото; малые файлы — прежний транспорт.
Оставшиеся задачи 1С по атомарной дедупликации, проверке потерянного ответа
и метаданным вложений описаны в `MEDIA_BUFFER_1C_2.8.1.md` и остаются актуальны.

## Проверки и выпуск

Проверяются отказ/пустой профиль/другой сотрудник в ответе 1С, обновление
просроченного и отозванного ключа, параллельный запуск, смена пользователя
во время запроса, разделение контуров и отсутствие поля ввода кода.
Полный набор npm test и сборка обязательны. APK получает прежнюю совместимую
подпись локально; ключ подписи не передаётся в GitHub CI.

Выпуск: отдельный PR, существующие main workflows, точный SHA и штатный
backup/rollback. Новые env или изменения Nginx не нужны. StateDirectory и
IndexedDB сохраняются при обновлении и откате.
