База: `22e37e2a4b50d2788ad4a97c429d942a859f4bc3` — GitHub main и production 2.7.13.
Версия: 2.8.0 / Android 2800 / ru.eazia.imax.

Владелец уже разрешил реализацию, deployment и APK 2.8.0 в текущем разговоре.

Окончательный merge SHA и APK должны быть взяты из GitHub Release v2.8.0, а не
из старого локального каталога или этого предрелизного SHA.

## Состав

Видео без прежнего клиентского порога 15 МиБ: Blob в IndexedDB, бинарный запрос
к Node, потоковое преобразование в прежний JSON 1С. Обновление только I-MAX
Nginx location. Неактивная завершённая приёмка, отдельная дефектовка в МП,
статус акта, фиксированная навигация, ограниченные экраном меню и история,
четыре размера текста/блоков. Список файлов: `git diff --name-only
22e37e2a4b50d2788ad4a97c429d942a859f4bc3..0971bd90b83056f40a297ca018c2aa8d925a69ab`.

## Выпуск и последующая работа

1. Fetch актуального GitHub main, проверить health SHA на Timeweb и diff.
   Если выпуск уже выполнен, начинать следующие изменения от новой main.
2. В чистой копии: npm ci, npm test, npm run test:review, npm run build.
3. Штатный PR в main; build/deploy только для точного merge SHA. Не загружать
   старый dist вручную и не переносить TEST overrides.
4. До merge установить новую версию deploy-max.sh с отдельным backup скрипта.
   Workflow сохранит application и Nginx snippet, проверит SHA после запуска.
5. Скачать unsigned release из Actions именно merge SHA. Подписать локально
   существующим ключом с сертификатом 906BA322884FCA8C92C2D884CDEBB8EC8F4EB3D527BAF7D06929970BA77BCB47.
   Не экспортировать keystore в GitHub, не создавать новый ключ.
6. Проверить package, versionCode, встроенный SHA/API, сертификат, zipalign и
   SHA256 файла. Итог: I-MAX-2.8.0.apk, GitHub Release v2.8.0.

## Проверено и ограничения

Полные 28 наборов тестов, build и review прошли. Браузер: настройки четырёх
размеров, история, fixed tabs, чат, клавиатура и ориентация. Видео >40 МиБ
побайтно проверено на локальном тестовом приёмнике для всех трёх маршрутов.
Старая очередь сохранена при IndexedDB 2→3, Blob переживает повторное открытие.

Физические Android/iPhone, реальное большое видео в 1С и её инфраструктурные
лимиты не объявляются проверенными. Закрытые вкладки/приложение не гарантируют
продолжение JavaScript: очередь возобновится при открытии владельцем.
Не удалять IndexedDB; закрыть старые вкладки перед обновлением. Старые клиенты
со схемой 2 не смогут обслуживать новую очередь схемы 3.

1С пока не отдаёт статус акта: требуется документ app-max/docs/1C_RELEASE_2.8.0.md.
Без поля статус серый, а не ошибочно красный. Unknown-source/Play Protect —
системное предупреждение, не отключать защиту и не обещать исчезновение.
План резервирования и отката: app-max/docs/RELEASE_2.8.0.md.
