# Альфа-Авто 6.1 — новый WEB-тренажёр (документальная сверка v2)

**Статус:** промежуточная версия для проверки; **не** копия авторизованной тестовой базы и не финальная приёмка по внешнему виду.

## Запуск

Откройте `Альфа-Авто_Тренажер_v2_по_инструкциям.html` двойным щелчком в актуальном Chrome / Яндекс Браузере / Edge. Интернет и доступ к 1С не требуются. Либо разместите `index.html`, `app.js` и `styles.css` в одной папке на обычном статическом хостинге.

## Какие инструкции использованы непосредственно

- `Инструкция_мастера-приемщика_1С_Альфа-Авто_6.1(2).docx` — исходный общий маршрут работы.
- `CRM Событие и система задач (1).pdf` — событие, контрагент, автомобиль, привязка документов, проведение.
- `Инструкция создания автомобиля(1).docx` — порядок VIN → шасси → поиск → выбор → применить.
- `Создание карточки Контрагента.docx` — форма «Юридическое лицо» → ИНН → «Найти и заполнить» → выбор → для ИП смена формы → «Заполнить».
- `Изменения в задаче CRM.docx` — обе даты записи с временем, допуск 0–60 дней, «Общий вопрос», содержание задачи.
- `Работа КП(1).docx` — необходимые реквизиты, вкладки авторабот/товаров и массовый подбор.
- Остальные приложенные инструкции по MAX, Email, экспресс ЗН, автоматической КП и блокировкам — для сверки остальных модулей; полная переделка этих модулей **ещё не выполнена**.

## Изменения v2 относительно собственного v1 (не относительно v13.1)

1. `Событие`: выбор причины переносит её краткое название в пока пустую «Договорённость с клиентом», затем ученик должен самостоятельно описать договорённость. При проведении обязательны поля и действия, перечисленные в PDF; отдельно не выдумывается обязательность поля «Причина обращения». Поиск автомобиля по фрагменту госномера или окончанию VIN теперь фильтрует учебный список. Если номер и VIN пусты, показывает автомобили выбранного контрагента.
2. `Карточка контрагента`: поиск по ИНН открывает окно выбора, не подставляя готовый ответ в форму. После выбора отдельная кнопка «Заполнить». Для ИП — подтверждение и смена формы собственности.
3. `Карточка автомобиля`: VIN и шасси перенесены **до** выбора марки и модели; добавлены поиск, учебное совпадение либо ручной выбор, кнопка «Применить». Далее ученик сам вводит госномер, цвет, комплектацию. Валидируется 17-значный VIN, запрещённые символы и дата выпуска.
4. `Задача CRM`: оба поля записи КО принимают **дату и время**, проверяется интервал от текущей даты до +60 календарных дней. После записи даты добавляются в содержание задачи (если не отмечен «Общий вопрос»).
5. `Калькуляция`: проверяются четыре обязательных реквизита — контрагент, договор взаиморасчётов, автомобиль и способ оплаты; требуется хотя бы одна реально заполненная авторабота. Подбор позволяет отметить несколько позиций и завершить подбор одним действием. Пустые количества и цены заполняет сам ученик.
6. Выбор в массовом подборе сохраняется при поиске. Повторная запись карточек не добавляет дубликаты учебной записи по одному ИНН/VIN.

## Проверки

- `node --check app.js` — успешно.
- `node qa/test_static.js` — 24/24 проверки пройдены: 15 генераторов экранов и 9 сценарных проверок (логика без реального браузера).
- Полноценный Chromium/Playwright прогон **не проведён**: среда блокирует открытие и локального `file://`, и `http://127.0.0.1`, возвращая `ERR_BLOCKED_BY_ADMINISTRATOR`. Нельзя выдавать эту сборку за полностью прошедшую браузерную регрессию.
- Посетить живую тестовую базу `https://1c.eazia.ru/aa6_ea_test9/ru/` из этой среды не удалось: DNS не разрешается; удалённая версия 1С **не просмотрена**.
