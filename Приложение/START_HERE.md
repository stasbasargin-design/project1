# ИТУС MAX 2.1 — обновлённый интерфейс и размещение на ea-itus.ru

## Что готово

Приложение сохраняет прежние разделы, последовательность кнопок и полей, сценарии приёма, дефектовки, УРВ и чатов. Использован присланный логотип. Обновлены цвета, карточки, поля, кнопки, окно дефектовки, состояния выбора и оформление сообщений. Красный — цвет действий, зелёный и жёлтый остаются цветами статусов.

Добавлены видимый фокус для клавиатуры, поддержка уменьшения анимации и индикатор внизу страницы. Индикатор показывает время последнего успешного ответа 1С, ошибку последнего запроса или отсутствие интернета. Он не заменяет внешний мониторинг: при закрытом приложении проверок нет.

Пути ресурсов и API подготовлены для https://ea-itus.ru/p/max-service/; локальный запуск в корне также работает. Пустой адрес без завершающего слеша перенаправляется на правильный с сохранением параметров MAX ID. Файлы обновляются без использования устаревшей дневной копии из кэша.

## Запустить у себя

Установить Node.js 20 или новее. Распаковать архив, запустить START_WINDOWS.bat и открыть http://localhost:8080/p/max-service/. Готовая папка dist включена. Установка npm-зависимостей для обычного запуска и сборки не требуется.

Пересборка: npm run build. Режим разработки Vite сохранён через npm run dev.

## Размещение на существующем сайте

Подготовлен вариант для Linux VPS с Nginx и Node.js. Если сайт размещён на обычном shared-хостинге без Node.js, этот вариант нужно адаптировать к возможностям хостинга.

Приложение размещается в /opt/itus-max, работает отдельной службой на 127.0.0.1:8080 за Nginx. Внешний адрес — https://ea-itus.ru/p/max-service/. Не открывайте порт Node.js наружу; для посетителей используется HTTPS сайта.

Администратору:

1. Сохранить резервную копию текущего приложения и конфигурации Nginx.
2. Проверить установленный Node.js и свободен ли порт 8080. Если занят — выбрать другой и одинаково указать его в файле окружения и proxy_pass.
3. Создать отдельного системного пользователя itus без интерактивного входа. Разместить файлы комплекта в /opt/itus-max с правом чтения и прохода по каталогам для этого пользователя.
4. Скопировать deploy/itus-max.env.example в /etc/itus-max.env, задать права 600 для root. Systemd загрузит его до смены пользователя.
5. Указать ONE_C_TARGET — адрес нужной публикации 1С; ONE_C_TOKEN — серверный секрет, если его требует 1С. Сейчас в примере сохранён адрес из прежнего комплекта: https://1c.eazia.ru/aa6_ea_test9/ru/hs/max-service. Это не подтверждённая рабочая база. Отображаемый адрес ONE_C_PUBLIC_BASE_URL в config/itus.config.js тоже обновить и выполнить npm run build.
6. Скопировать deploy/itus-max.service в /etc/systemd/system/itus-max.service. Проверить путь /usr/bin/node (команда command -v node), исправить ExecStart при необходимости.
7. Выполнить systemctl daemon-reload и systemctl enable --now itus-max. Проверить systemctl status itus-max.
8. В существующий HTTPS server-блок ea-itus.ru добавить только содержимое deploy/ea-itus-location.conf. Не заменять конфигурацию сайта целиком. Если location для этого пути уже есть — обновить именно его, не создавать дубликат. TLS, остальные страницы и действующие правила доступа сайта сохранить. Директива ^~ выделяет маршрут приложения; при существующей защите доступа администратору нужно явно сохранить её для этого location.
9. Проверить nginx -t и только после успеха выполнить systemctl reload nginx.
10. Открыть https://ea-itus.ru/p/max-service/; проверить загрузку, вход пользователя, список ЗН, приём, фото/микрофон и серверные права на действия. /p/max-service/health проверяет сервер приложения, но не соединение с 1С.

Секреты не записываются в браузерную конфигурацию. Служба автоматически перезапускается после сбоя, журнал доступен через journalctl -u itus-max. Это не уведомления в MAX о недоступности; такую проверку можно добавить отдельным этапом.

Для настройки кнопки запуска мини-приложения MAX используйте указанный HTTPS-адрес. Идентификаторы ботов в конфигурации сохранены из исходного проекта; значения PASTE_* требуют вашей настройки при использовании этих интеграций.

## Что не менялось

Состав вкладок и их порядок, расположение действий внутри разделов, методы бизнес-операций 1С, передача MAX ID, серверная модель прав и состав полей анкеты не переработаны. Доработки required и счётчика из предыдущего комплекта сохранены. Подробности — UPDATE_2026-09-09.md. Фотография по умолчанию обязательна; 1С может передать acceptance.photo.required: false.

Графика значков разделов сохранена: исходного Figma-файла нет. Новый логотип взят из предоставленного изображения и показан в прежнем месте без перерисовки.

## Проверки

Успешно выполнены проверки синтаксиса, тесты нормализации JSON, регрессионные тесты приёма и тест реального HTTP-сервера на подставной 1С:

- node tests/api-normalizers.test.mjs
- node tests/acceptance-regression.test.mjs
- node tests/subpath.test.mjs

Проверены required, успешная/ошибочная отправка фото, JSON завершения, исходные значения, кнопки разделов, курсор, локальные и вложенные пути, загрузка ресурсов, сохранение параметров при перенаправлении, серверный токен и ответ 404 для отсутствующих файлов.

Визуальная проверка на устройствах и интеграция с рабочей 1С не выполнены. Архив не был размещён на ea-itus.ru: доступа к управлению хостингом в этой сессии нет.

## Что можно добавить следующим этапом

1. Внешняя проверка доступности приложения и 1С с уведомлением в MAX.
2. Защита от потери незавершённой анкеты с согласованным сроком хранения и привязкой к сотруднику/ЗН.
3. Проверка подлинности входа из MAX на сервере: сейчас ручной ID сохранён как в исходной версии, самостоятельным доказательством личности он не является. Перед внешним запуском администратор должен проверить действующие серверные ограничения доступа.

Эти изменения требуют отдельных решений по серверу и процессу. В текущий комплект они не внедрены.
