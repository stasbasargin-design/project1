# ИТУС 2.6.5 — формирование пакета УРВ

Рабочая сборка на основе полного архива itus-site-v2.6.1-ready.zip и файлов исправления уведомлений ITUS_MAX_UPDATE_v2.6.3.zip. Исходные архивы не изменены. Номер 2.6.5 обозначает эту доработку.

## Что реализовано

В разделе «Исполнитель» кнопка «Создать пакет УРВ» открывает форму. Сначала приложение получает работы выбранного ЗН, затем список исполнителей его цеха. Работы выбираются на первом шаге. На втором шаге — кнопка «Делаю сам» и список коллег; для совместной работы есть отметка «Я участвую». Для нескольких участников проценты вводятся в отдельном окне, для одного автоматически устанавливается 100%. Перед отправкой — отдельное подтверждение состава. Выбранные работы и участники передаются при создании пакета. До создания ссылка packageRef не используется.

| POST метод | Тело запроса сверх общей оболочки | Результат data |
| --- | --- | --- |
| /worktime/orders/works | orderRef, withoutActivePackages: true | workshopRef, works: [{workRef, name, available}] |
| /worktime/executors/list | orderRef, workshopRef | executors: [{employeeRef, name, workshopRef, available}] |
| /worktime/participation/validate | orderRef, workshopRef, workRefs, participants (приложение также передаёт clientPackageId) | valid: true |
| /worktime/packages/create | orderRef, workshopRef, workRefs, participants, clientPackageId | package: {packageRef, status} |
| /worktime/packages/start | orderRef, packageRef | прежний ответ package |
| /worktime/packages/pause | orderRef, packageRef | прежний ответ package |
| /worktime/packages/close | orderRef, packageRef | прежний ответ package |

Состав участников сохраняется атомарно при create. Проверка participation/validate не создаёт пакет и не записывает распределение отдельно. Редактирование состава уже созданного пакета в эту доработку не входит.

Пример бизнес-полей POST /worktime/packages/create:

```json
{
  "orderRef": "ORDER_GUID",
  "workshopRef": "WORKSHOP_GUID",
  "workRefs": ["ORDER_WORK_ROW_GUID"],
  "participants": [
    {"employeeRef": "EMPLOYEE_GUID", "percent": 60},
    {"employeeRef": "COLLEAGUE_GUID", "percent": 40}
  ],
  "clientPackageId": "UUID_STABLE_FOR_RETRY"
}
```

Общая оболочка call1C сохраняется: requestId, timestamp, userId/maxUserId/authId, authMode, max, miniApp, version и существующие дополнительные поля ЗН. Прокси сохраняет тело, прежние заголовки авторизации и адрес публикации. Полные примеры находятся в 1C_HTTP_METHODS_RELEASE.json. MAX_JSON_SCHEMA_RELEASE.json не менялся: формат MAX прежний.

## Обязательные изменения на стороне 1С

В переданном архиве нет конфигурации или расширения 1С, поэтому обработчики 1С здесь НЕ реализованы и соединение с рабочей базой не проверено. Приложение и прокси реализуют вызовы и структурную проверку. До включения этой версии в работу нужно добавить в HTTP-сервис 1С три новых метода и расширить create по контракту.

1. works возвращает строки работ конкретного ЗН. workRef — стабильный идентификатор строки, а не ссылка общего справочника работ; одинаковая услуга может встречаться несколько раз. available=false обозначает недоступную строку.
2. executors/list проверяет доступ авторизованного пользователя к ЗН и цеху; возвращает доступных сотрудников, включая коллег. Отсутствующий текущий пользователь не добавляется клиентом искусственно. Не доверять workshopRef и userId из тела без проверки существующим механизмом авторизации.
3. participation/validate проверяет права, принадлежность работ ЗН, сотрудников цеху, их доступность и доли. Успех — success:true,data:{valid:true}. Ошибка — прежняя оболочка success:false,error:{code,message,details} и соответствующий HTTP-код. Неизвестный метод не подменяется успешной проверкой на клиенте.
4. create повторяет все проверки в транзакции: предварительная проверка не исключает конкурентных изменений. Не допускать повторного включения недоступных работ. Создание пакета, запись работ, исполнителей и процентов — атомарно.
5. clientPackageId обеспечивает идемпотентность создания: тот же ключ и состав возвращают тот же packageRef; иной состав с тем же ключом возвращает 409. Ключ нужно связать с авторизованным пользователем и ЗН. requestId остаётся идентификатором отдельного HTTP-запроса. Клиент сохраняет clientPackageId при повторе в открытой форме, в том числе после потери ответа; при повторном открытии формы того же ЗН после неопределённого результата сохраняются состав и ключ. После перезагрузки страницы или открытия формы другого ЗН ключ не сохраняется. При неопределённом результате сначала проверить созданные пакеты в 1С, не начинать новую форму вслепую.
6. participants — непустой массив, уникальные employeeRef, доли — JSON-числа строго больше 0 и не больше 100, не более двух десятичных знаков. Сумма ровно 100.00; в браузере/прокси сумма считается в сотых процента, без округления пользовательских долей. В 1С использовать десятичную арифметику с теми же ограничениями.

Старые маршруты start/pause/close и production сохранены. Старый вызов create только с orderRef и пустым packageRef теперь намеренно отклоняется как неполный: он не содержит выбранных работ и участия. Клиент и HTTP-сервис 1С необходимо обновлять согласованно. При прямом подключении клиента к 1С структурная серверная проверка Node обходится, поэтому проверка в 1С обязательна.

## Проверка и консоль

Локальная проверка без установки зависимостей: Node.js 22+, `npm run build`, `npm test`, `npm run test:review`.

Для демонстрации: `npm start`, открыть http://localhost:8080/preview.html?role=executor. Все данные этого режима находятся в памяти браузера, запросы к рабочей 1С не отправляются. Выбрать «Исполнитель» → «Создать пакет УРВ» → работы → подтвердить → «Делаю сам» или сотрудники → подтвердить → для нескольких участников доли 60 и 40 → подтвердить состав. Под приложением раскрыта консоль фактических запросов демонстрации. Для проверки ошибки указать 60 и 30.

В обычной версии открыть инструменты разработчика, вкладку Console:

```js
ITUS_WORKTIME_CONSOLE.methods(); // показать методы
ITUS_WORKTIME_CONSOLE.enable(); // включить журнал до открытия формы
// Выполнить действия в форме приложения.
ITUS_WORKTIME_CONSOLE.show();   // последние 30 запросов, без токенов и контекста MAX
ITUS_WORKTIME_CONSOLE.disable(); // очистить журнал и выключить запись
```

В обычной версии журнал по умолчанию выключен. В демонстрации включён автоматически. WORKTIME_CONSOLE_LOG.json — реально снятые сообщения браузера: works → executors → validate → create (журнал новой пошаговой формы). Значения review-* являются тестовыми ссылками.

## Развёртывание

Нужны обновлённые assets/app.js, assets/api-normalizers.js, новый assets/worktime.js, index.html и пересобранный dist, а также server.mjs для серверной валидации. Новая зависимость server.mjs — assets/worktime.js в корне приложения, не только копия внутри dist. Файлы уведомлений v2.6.3 включены. Существующие конфигурацию, секреты и данные сервера необходимо сохранить. Если используется отдельный портал server.js из другого проекта, его код не входит в этот архив: серверную проверку нужно перенести в его прокси отдельно.

Сначала обновить и проверить методы на тестовой базе 1С, затем выкладывать приложение с резервной копией. Скрипты установки предыдущих релизов сохранены как исходные материалы; автоматически на сервере они не запускались.
